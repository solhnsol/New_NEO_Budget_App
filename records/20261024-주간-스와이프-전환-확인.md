# 주간 스와이프 전환 확인 (2026-10-24)

## 확인한 것
폰 빌드와 같은 구성(hstee5 + PR #1~#5, PR #5와 합칠 때 `FixedGridBrowseView`의 시간축 라벨 주석만 충돌해 PR #4 쪽을 따랐어요)을 별도 시뮬레이터(iPhone 18 Pro, iOS 27)에 설치해, 상단 주간 띠를 앞뒤로 스와이프하는 모습을 화면 녹화로 찍어 0.05초 간격 프레임으로 봤어요.

- 앞(다음 주): 떠나는 공과 캡슐이 날짜와 함께 왼쪽으로 사라지는 건 맞았지만, 새 주의 공이 제자리에 붙지 않고 옛 자리에서 새 날짜 쪽으로 가로질러 날아갔고, 떠나는 공은 처음부터 흐릿하게 나타났어요. 떠나는 공 속 숫자도 파란 글씨가 되어 안 보였어요.
- 뒤(지난 주): 같은 이유로 어긋났어요(좌우 코드는 같아서 대칭).
- PR #4·#5가 `WeekStripView`에 한 건 색 토큰 교체뿐이라 공통 레이아웃 변경과의 병합 문제는 아니었어요.

## 원인
공과 캡슐을 `.id`로 바꾸거나 목록에 넣을 때 SwiftUI의 기본 전환(투명도)이 따라붙었어요. 주가 바뀌는 동안은 띠가 애니메이션 중이라 이 전환이 켜져서, 사라지는 공은 옛 위치에서 끌려 다니며 흐려지고 떠나는 공·캡슐은 흐릿하게 나타났어요.

## 고친 것 (`WeekStripView.swift`)
- 새 공, 떠나는 공, 떠나는 캡슐에 `.transition(.identity)`를 줘서 기본 전환을 끔.
- 주 스와이프로 떠나는 공 위의 숫자는 떠나는 동안 공 위에 있던 모양(흰 글씨)을 유지.

## 다시 확인
같은 방법으로 앞·뒤 모두, 공과 캡슐이 기존 위치에 붙은 채 날짜와 함께 화면 밖으로 나가고 새 주에서 새로 나타나는 것을 봤어요. 날짜 탭 이동은 그대로예요.
