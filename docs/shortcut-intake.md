# 단축어로 실제 알림 받기

## 흐름

1. iOS 단축어 자동화가 금융 앱 알림을 사전(`app`, `title`, `subtitle`, `body`, `timestamp`)으로 만든다. 서버로 보내던 그 사전이다.
2. 자동화의 마지막 단계는 앱 동작 **OnAll · 알림 기록하기**(`RecordNotificationIntent`)다. "알림 JSON"에 사전을 넣는다. 앱은 열리지 않는다.
3. `ShortcutNotificationDecoder`가 `RawNotification`으로 바꾼다.
   - 예전 모양 `{app, message, timestamp}`, `{message, timestamp}`도 읽는다(`message`는 본문).
   - 배열이면 여러 건으로 읽는다.
   - 시각은 기기 형식("Oct 8, 2026 at 11:41:17 PM", 좁은 공백 포함), ISO8601, epoch를 읽는다. 못 읽으면 받은 시각을 쓴다.
   - ID는 보낸 내용의 SHA-256이다. 같은 알림을 두 번 보내도 한 건이다. 시각이 없으면 받은 시각까지 넣어서 서로 다른 알림이 합쳐지지 않게 한다.
4. `NotificationIntake`가 한 건씩 처리한다: 파서 → 계좌 근거 → 등록부(새 번호는 계좌 후보로) → 조립 → Correlator → 처리 저장소(중복 검사, 승격).
5. 앱은 받은 알림(`notifications.json`)과 계좌 설정(`setup.json`)만 Application Support/Intake에 저장한다. 원장은 저장하지 않는다. 실행할 때와 계좌 답이 바뀔 때마다 `IntakeLedger`가 받은 순서대로 다시 재생해서 원장을 만든다.

## 사용자가 답하는 것

가계부 탭 오른쪽 위 **받은 알림**에서 답한다.

- **이 계좌가 맞나요?** 알림에 처음 나온 계좌번호나 카드 상품이다. 답은 셋 중 하나다.
  - 새 계좌로 등록: 잔액은 0원에서 시작한다.
  - 이미 등록한 계좌와 연결: 예를 들어 체크카드를 그 결제 계좌에 연결한다.
  - 내 계좌 아님.
- **어느 계좌인가요?** 번호를 말하지 않는 알림이다(토스 결제, 카카오페이 충전, 교통카드). 같은 앱이 보내는 같은 종류 알림을 고른 계좌로 보내는 규칙을 만든다. 같은 기관에 다른 계좌가 있으면 규칙이 추측이 되므로 만들지 않고, 그 알림은 검토로 남는다.

## 아직 없는 것

- 시작 잔액을 직접 입력하는 화면. 지금은 0원부터 알림으로 움직인 만큼만 센다. Actual Budget에서 가져온 계좌만 시작 잔액이 있다(`docs/actual-budget-import.md`).
- 검토 대기 거래를 직접 확정하거나 고치는 화면. 환불 짝 고르기, 남의 계좌로 보낸 송금 등이 여기에 해당한다.
- 받은 알림이 아주 많아질 때의 저장 방식. 지금은 파일 하나를 통째로 다시 쓴다.
