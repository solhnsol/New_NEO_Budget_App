# 정각 중심 시간축 (DEBUG 그리드)

기준: `8b6df95` 위에서 DEBUG 그리드만 변경(Browse 변경 없음). 시뮬레이터 스크린샷·녹화는 이 폴더에 있다.

## 정책
- **정각 전용 분할** `TemporalGridParameters.hourly(slotCount:)`: 후보 경계는 HH:00만, 칸은 최소 1시간(따라서 30분 미만 칸 없음), 최대 8시간. 짧은 일정이 밀집해도 칸을 쪼개지 않는다. 5분 후보 방식(`.default`)은 비교용으로 유지. 30분 칸 허용(`halfHour`)은 실험 비교용일 뿐 정책이 아니다.
- 한 시간보다 짧은 일정은 칸 안에서 높이로 정확히 표현되지만, 제목을 쓸 높이를 얻지 못하는 일이 많다. 그런 claim도 주변 칸을 한 시간 쪽으로 당기도록 탐색에 남겨 둔다(`keepsPartlyServableClaims`, 정각 전용 기본값; N=12 날짜 이동 평균 Y가 112.9 → 58.6).
- 동일 높이 칸, 고정 전체 높이, 고정 가로줄, 공유 시간축, 압축 레일은 그대로.
- **시간축 눈금**: 모든 정각(0~24)의 실제 Y(`timeToY(h·60)`)에 축(gutter)에만 눈금을 그린다(그리드 안에 가로줄 추가 없음).
- **라벨 선택** `HourTickPlan`: 라벨 높이(10pt 폰트 줄 높이 12)+여백 4 = 최소 간격 16pt. 그리드 경계 시각을 먼저, 이어서 남는 정각을 "이미 고른 라벨에서 가장 먼 것" 순서로 추가(균형 배분). 각 라벨이 나타나는 줌을 한 번 계산해 두므로(앞의 우선순위 prefix = 항상 중첩 집합) 확대하면 라벨이 추가만 되고 축소하면 역순으로 사라진다(깜빡임 없음). 라벨은 필요 줌에서 opacity 0 → 0.15 줌 뒤 1로 점진적으로 나타난다. 첫/마지막 라벨은 축 가장자리에 붙이고, 가장자리에서 잘리는 라벨은 잘리지 않는 줌까지 기다린다.
- 전환 중(p): 눈금은 보간된 파티션에서 정각의 실제 Y를 쓰고(임의 시각은 쓰지 않음), 레일은 A/B 스타일 페이드, 가로줄은 고정.
- 압축 칸의 길이 태그("3시간")는 라벨과 겹쳐 제거했다. 시간 범위는 굵게 표시되는 경계 정각 라벨(예: 04:00 / 07:00)로 읽는다.

## 검증
- 테스트(`TemporalGridHourlyTests`): 모든 fixture × N=10/12/16에서 경계 전부 정각, 칸 ≥ 60분(30분 미만 0), 칸 수·동일 높이·전체 높이 고정; 정각 좌표 `timeToY`/`yToTime` 왕복 1e-9(확대 2.5배 포함); 줌 1~3(0.05 간격)에서 라벨 충돌 0건, 줌 증가 시 라벨은 추가만 됨(깜빡임 없음), 가장자리에서 잘리는 라벨 없음, 경계 정각 라벨이 먼저, 라벨이 점진적으로 나타남, 추가가 균등 분포. 날짜 전환 중 가로줄 고정은 기존 보간 테스트(`TemporalGridPartitionTests`/`ReadabilityTests`)가 계속 보장한다.
- 스크린샷: `dense-n10/n12/n16`, `dense-fine5min`(비교), `dense-zoom1/2/3`, `events32(-zoom2)`, `text3x(-zoom2)`, `transactions-dense`, `trans-p0/0.25/0.5/0.75/1`. 녹화: `zoom-1-3-1.mp4`(줌 1→3→1에서 라벨이 점진 추가·역순 제거), `swipe-p0-1.mp4`(p 0→1에서 가로줄 고정, 눈금이 정각 Y에 따라 이동).
- 화면 조작: `-grid-policy hourly|fine`(기본 hourly), 화면 상단 "정각/5분" 토글, `-grid-script zoom|swipe`.

## 남은 문제
- 제목 표시 감소(위 표). 정각 정책을 쓰려면 짧은 일정의 제목을 확대/선택으로 얻는 경로가 필요하다.
- N=12 정각 전용의 날짜 이동 안정성(기본 설정에서 5분 후보보다 큼). 부분 claim 유지로 완화되나 fixture별 편차가 크다.
- 압축 칸 길이 표시(예: "3시간")는 제거했고 경계 정각 라벨로만 읽는다. 경계가 4개 이상 연속 압축되는 경우의 가독성은 실기기 평가가 필요하다.
- 라벨 크기(10pt)는 Dynamic Type을 따르지 않는다(눈금 축은 고정 폰트). 큰 글자에서의 축 라벨 크기 정책이 필요하다.
