# 인터랙티브 핀치 줌 (DEBUG Temporal Grid)

기준 `7006212`. DEBUG `-render-grid` 화면만 변경(Browse·EventKit·Focus·편집 변경 없음). 정각 분할·고정 N칸·`EventPresentation`·압축 레일·정각 눈금 라벨 선택을 그대로 쓴다.

## 구현
- `PinchZoomMath`(순수): 줌 범위 1~8, 고무줄(`d·L/(L+d)`: 경계에서 기울기 1, 위 +0.6/아래 −0.12에서 포화), 앵커 보존 `offset = fraction·V·z − focal`, 오프셋 범위, 해제 시 복원 목표, 슬라이더 줌의 앵커 유지, 화면 밖 구성 제외용 밴드.
- `PinchZoomScrollView`(UIKit, DEBUG): `UIScrollView`(관성·가장자리 바운스는 UIKit 그대로) 안에 SwiftUI 그리드. 핀치는 `UIPinchGestureRecognizer`의 두 손가락 **중심**(`location(in:)`)을 매 프레임 읽어 확대와 팬을 함께 처리: 시작 시 중심 아래 시각의 그리드 비율 u를 잡고 `offset = u·V·z − 중심y`로 매 프레임 `contentSize`/`contentOffset`을 한 번에 적용(콘텐츠와 스크롤이 어긋나지 않음). 1×·8× 밖은 늘어났다가 손을 떼면 0.32s ease-out으로 복원(역방향 핀치는 단조라 즉시 반응, 복원 애니메이션 중 새 핀치는 즉시 중단).
- 제스처 중재: 핀치 시작 때 스크롤 pan·날짜 이동 pan을 끄고 `TouchCounter`(제스처 인식에 참여하지 않는 터치 수 계수기)가 모든 손가락이 떨어질 때까지 유지 → 핀치 후 남은 손가락이 스크롤·날짜 이동을 오발하지 않음(안전장치: 1.5초 뒤 복귀). 날짜 이동은 가로가 우세한 한 손가락 드래그만 시작하고(속도비 1.6) 핀치와 동시에 진행되지 않는다. 날짜 이동은 `p`를 직접 움직이고 놓으면 가까운 날로 스냅하며 **줌 배율은 유지**한다.
- 성능 구조: 분할(DP)·눈금 계획은 메모(`StateMemo`)로 키가 같으면 스토어에 접근조차 하지 않는다. 핀치 프레임은 확대된 파티션을 만들고 배치(`GridPlacement`)·글자 충돌(`GridTextLayout`)·눈금 opacity만 계산한다. 하루의 정적 엔티티는 날짜마다 한 번만 생성. 화면 밖(±1 viewport) 일정·거래는 뷰를 만들지 않고, 스크롤은 반 viewport 밴드가 바뀔 때만 다시 구성한다(스크롤 프레임마다 재구성 없음).

## 측정
- 앵커 시각 오차(테스트, 결정적 의사난수 300회 × 20스텝 = 6000스텝, 중심 이동·확대/축소 반복): 오프셋이 한계에 닿지 않는 스텝에서 **최대 오차 < 1e-6분**. 한계에 닿는 스텝(그리드 끝)에서는 오프셋이 끝에서 멈추며 시각이 고정되지 못한다(정상).
- 시간 좌표: 줌 1~8(0.37 간격)에서 모든 정각 `y = base·zoom`(오차 < 1e-9), `yToTime(timeToY(m))` 왕복 < 1e-9, 경계 불변.
- 충돌: 줌 1~8(0.2 간격) × 글자 ×1/×3 × dense/events32/text3x/거래밀집 fixture에서 쓰인 글자 사각형 충돌 0건, 눈금 라벨 간격 ≥ 16pt, 거래 묶음의 ID 합 = 독립 거래 수.
- 프레임 계산(Debug 빌드, 열 3개 × 32일정 + 눈금, 줌 1→8→1 240프레임): 모델 계산 **평균 0.50ms / 최악 2.9ms**, 분할 계획 0회·프로필 0회(120Hz 프레임 예산 8.3ms 중 모델 몫). 
- 시뮬레이터(60Hz)에서 핀치 중 실측: 디스플레이 링크 간격 중앙 16.7ms; SwiftUI 트리 구성(빌드 클로저) 평균 0.05~1.5ms(최대 6.7ms는 첫 핀치). 핀치 후 상태: 첫 핀치 15프레임 중 4프레임 지연(최대 33.8ms), 이후 핀치들은 0~3/15 지연. **실기기 120Hz는 측정하지 못했다.**
- 최적화 횟수: 핀치·스크롤·줌 복원 동안 증가 없음(상태줄 "최적화 N회"); 날짜 이동에서만 새 창 계획 2회 증가. (실행 직후 레이아웃이 한 번 바뀌어 초기 4회.)

## 실제로 확인한 범위 (iOS Simulator, 두 손가락 터치 주입)
- 1×에서 중심 핀치 → 4.3×(중심 시각이 같은 위치에 유지: 12:00이 y 중심에 머묾), 상단 가까이 핀치, 중심이 위로 이동하는 핀치, 핀치 인(→1×), 1× 아래로 과하게 줄임(0.89~0.91×로 늘어났다 1.00×로 복원), 8× 위로 과하게 확대 후 복원(녹화), 확대 후 한 손가락 스크롤(관성, 끝에서 24:00까지), 확대 상태에서 가로 스와이프로 날짜 이동(줌 4.12× 유지·스크롤 위치 유지) 확인.
- 화면: dense(상단 앵커), events32, text3x(×3 글자, 5×), 거래 밀집(6.3×; 14:00 대 묶음 배지, 1분 간격 거래는 8×에서도 9pt 미만이라 건수 배지로 남고 탭하면 목록) 스크린샷. 녹화 `pinch-session.mp4`(핀치 아웃 → 스크롤 → 중심 이동 핀치 → 핀치 인 → 8× 초과 → 날짜 이동).
- **확인하지 못한 것**: 핀치 후 손가락 하나만 남기는 상황(주입 도구가 두 손가락을 동시에 뗀다; 로직과 안전장치만 구현), 실기기 120Hz, 시스템 Dynamic Type 설정(글자 배율은 화면 내 ×1~×3 선택으로 확인).

## 남은 문제
- 콘텐츠를 프레임마다 SwiftUI로 다시 만든다(변환 레이어가 아님). 시뮬레이터 60Hz에서는 문제 없었지만 실기기 120Hz에서 8× 부근 지연이 있는지 측정이 필요하다. 레이어 변환(핀치 중) + 종료 시 재구성 방식이 대안.
- 날짜가 바뀔 때 스크롤 오프셋(pt)은 유지하지만 보이는 시각은 분할이 달라져 바뀐다. 시각 기준 앵커로 보정할지 결정이 필요하다.
- 1× 아래로 늘어나는 동안 그리드가 viewport보다 짧아져 아래가 비어 보인다(약한 고무줄, 최대 0.88×).
- 1분 간격 거래는 8×에서도 분리되지 않아 건수 배지가 최종 접근 경로다(거래 목록 UI 필요).
- 가로 날짜 이동 드래그는 이 화면용이며 제품 스와이프 상태 머신이 아니다.
