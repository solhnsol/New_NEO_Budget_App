# 실제 날짜 스와이프 (DEBUG Continuous Grid)

기준 `49f34ce`. 기존 `DayMoveModel` / `DayAxisGeometry` / `ContinuousDayAxis`를 그대로 쓰고 새 상태 머신은 만들지 않았다. Browse·EventKit·편집·Focus 불변.

## 변경
- **입력 분류** `HorizontalDragClassifier`(순수, `DateSwipeInput.swift`): 한 손가락 샘플(시간 포함)에서 가로(스와이프) / 세로(스크롤) / 미결정을 판정(가로 4pt 이상이고 세로의 1.4배 이상 → 스와이프, 세로 6pt 이상이고 가로의 1/1.4 초과 → 스크롤; UIKit pan의 약 10pt보다 빠르다). 이동량은 **손가락이 닿은 점 기준**이라 인식 순간에 콘텐츠가 이미 손가락 아래에 있다. 속도는 마지막 80ms, 멈춘 손가락(80ms 이상 경과)은 0.
- **제스처** `DateSwipeRecognizer`: 한 손가락만 추적, 두 번째 손가락이 닿으면 취소(핀치로 넘김), 세로면 실패(스크롤로 넘김). 핀치 중·직후(모든 손가락이 떨어질 때까지)에는 시작하지 않는다.
- **연결(화면)**: 가로 변위 ÷ `dayWidth` = position 변화(선형), 놓을 때 `release(velocity: 일/초)` → `DayMoveModel`이 이동 거리·속도로 착지 날짜를 정한다(플릭은 0.15초 앞, 최대 3일). 드래그·정착 모두 같은 `position`에서 시간 분할 보간·정각 눈금·열 위치가 계산된다.
- **즉시 인계(입력 무시 시간 없음)**: 정착 중 손가락이 닿으면 그 자리에서 멈추고(`touchDown`→`beginDrag`, 위치·단계 유지) 스와이프가 되면 그대로 인계, 스와이프가 아니면(손가락 뗌) 원래 목표로 이어서 이동(`touchUp`→`retarget`). 이동 중 새 드래그는 현재 위치에서 점프 없이 시작.
- **앵커 `AnchorState`** (`ContinuousDayAxis.swift`): 뷰포트 중앙 시각을 잡고 위치가 바뀔 때마다 그 시각이 중앙에 오는 오프셋을 계산. **스크롤/핀치가 이동을 끊으면 안전하게 재설정**: 사용자가 스크롤·핀치한 뒤 첫 스텝에서 사용자가 남긴 오프셋을 기준으로 앵커 시각을 새로 잡는다. 사용자가 스크롤을 쥐고 있는(드래그·관성) 동안은 오프셋을 덮어쓰지 않는다. (손가락이 닿기만 한 상태는 스크롤이 아님: 처음 구현에서 `isTracking`을 스크롤로 오판해 스와이프마다 앵커가 조금씩 어긋나는 문제를 시뮬레이터에서 발견해 고쳤다.)
- **열 수 비종속**: 화면의 날 수는 `visibleDayColumns` 한 곳(현재 2)이고 기하·열 배치는 모두 `DayAxisGeometry(visibleColumns:)`를 따른다(테스트: 2/3/4열). 분할 계획은 여전히 창 하나가 앞 1일·뒤 2일을 읽는다(3열 이상은 계획 정책이 별도 결정 필요).

## 검증
- **테스트 `DateSwipeTests` 15개**(전체 352개 통과): 분류기(4pt/6pt, 대각선 판정, 인식 시 이동량 = 닿은 점 기준, 속도 창·멈춘 손가락·방향 전환), 스와이프 시뮬레이터(샘플 → 분류기 → 모델 → 80Hz 스텝): 선형 매핑(40pt = 40/170일), 짧고 느린 드래그는 원래 날로 복귀, 긴 드래그는 다음 날, 짧은 빠른 플릭은 다음 날·더 빠르면 더 멀리(hop 제한 3일), 뒤로 플릭, 취소(속도 0 해제 → 가까운 날), 이동 중 손가락 닿음(그 자리에서 정지, 이동 중 위치 불변, 뗌 → 목표로 계속), 비행 중 새 스와이프 인계(첫 프레임 점프 0, 이후 프레임당 최대 이동 < 0.12일, 방향 반전), 연속 4회 플릭이 하나도 무시되지 않고 누적(프레임당 최대 이동 < 0.2일, 최종 정지 위치 = 목표), 앵커 유지(오차 < 1e-6분), 스크롤·핀치로 끊길 때 앵커 재설정(새 앵커 = 사용자가 보던 시각, 줌이 바뀐 경우 포함), 스크롤을 쥐는 동안 앵커 해제 → 이후 첫 스텝에서 재취득, 날짜·시간축·열 위치가 한 position에서 나옴(열 간격 항상 dayWidth, 프레임당 정각 y 이동 < 6pt), 열 수 2/3/4.
- **프레임 비용**: 모델 스텝 + 앵커 계산 **0.059ms (Debug)**, 분할 계획 0회. 시뮬레이터 실측(60Hz): 스와이프 중 적용 비용 평균 0.06~0.09ms / 최대 4.4ms(첫 프레임), 디스플레이 링크 간격 중앙값 16.7ms, 지연 프레임 0~3/24~82(최대 33~37ms).
- **시뮬레이터 직접 조작**(줌 3×, 12:00 부근으로 스크롤 후; 패널 "스와이프 해제 …일/s → 목표"로 확인): 짧고 느린 드래그 후 멈춤 → 해제 0일/s → 원래 날로 복귀, 긴 드래그(200pt/0.5초) → 1.6일/s → 다음 날, 빠른 플릭 → 13일/s → hop 제한(3일), 플릭 직후 역방향 스와이프 2번(비행 중 인계) → 1일로 복귀, 앵커 시각은 모두 12:28 그대로(드리프트 없음), 플릭 직후 세로 스크롤(정착 중) → 정착은 목표(4일)까지 완료, 앵커 "—"(재설정)로 표시, 플릭 직후 핀치 → 줌 6.11×, 앵커 14:58로 재설정, 이어서 6.1×에서 스와이프 → 2일, 앵커 14:58 유지, 스크린샷 `a-…`~`f-…`, 녹화 `swipe-session.mp4`(위 전 과정, 약 1.5분). 녹화 영상 자체는 열어 보지 못했다.
- **확인하지 못한 것**: 스와이프 도중 두 번째 손가락이 닿아 취소되는 경로(주입 도구가 두 손가락을 동시에 시작해서 핀치로만 인식됨, 로직·단위 테스트만), 줌 8×와 줌 1×에서의 실제 스와이프, 실기기 120Hz.

## 남은 문제
- 정착 중 손가락이 닿았다가 스와이프가 아닌 채 떼면 속도 0으로 목표를 향해 다시 출발한다(원래 비행의 속도는 잃는다).
- 스크롤을 쥐는 동안에는 오프셋을 덮어쓰지 않으므로, 가로 이동 중 세로 스크롤을 하면 그동안 중앙 시각이 날 사이로 어긋나고 손을 떼면 그 자리에서 앵커가 재설정된다.
- 날짜 범위 끝(이 fixture는 1…5)에서는 hard clamp. 끝에서 약한 고무줄은 아직 없다.
- 3열 이상 표시는 분할 계획 정책(어떤 창을 읽을지)이 정해지지 않았다.
