# 가상 연속 날짜 그리드 (좌표계·상태 모델)

기준 `daea8f5`. DEBUG Temporal Grid만 변경(핀치·시간축·렌더링 계약 유지, Browse·EventKit·편집·Focus 불변). 실제 스와이프 제스처와 Browse 통합은 이번 단계가 아니다(화면의 가로 드래그/버튼은 모델을 검증하기 위한 DEBUG 입력).

## 모델 (모두 순수 값 타입, 뷰·시계·제스처 없음)
- **`DayAxisGeometry`**: 날짜마다 고정 폭 `dayWidth`를 갖는 무한 수평선. 날짜 d는 `x = d·dayWidth`에서 시작하고, 창의 위치 `position`(Double, 일 단위)은 창 왼쪽 가장자리의 날짜다. `x(ofDay:at:)`, 드래그 변위 → 위치, `visibleDays`(창에 닿는 날: 정지 시 2개, 사이에서 3개, 음수 날짜도 가능), `windows`(공유 시간이 읽는 창: 정지 시 1개, 사이에서 2개), `planningDays`(≤5일: 창 하나는 앞 1일·뒤 2일을 읽음). **그리는 날 = 보이는 날뿐**, 주변 날은 계획에만 쓰고 그리지 않는다.
- **`ContinuousDayAxis.partition(at:)`**: 위치의 공유 시간 분할 = 창 `floor(position)`과 `floor+1`의 분할을 `frac(position)`으로 직선 보간(반올림 없음). **수평 진행률과 시간 보간 진행률은 같은 숫자 하나다.** 분할 계획은 호출자가 주는 `windowPartition(w)`(캐시)에서 가져오며 여기서는 계획하지 않는다. 모든 열이 같은 이 분할 하나로 y를 계산한다.
- **앵커** `anchoredOffset(time:partition:zoom:viewport:focal:)`: 줌된 분할에서 `time`이 `focal`(뷰포트 중앙)에 오는 스크롤 오프셋. 그리드 끝에서 방 없으면 오프셋이 한계에서 멈추고 `clamped`와 잔차(분)를 돌려준다. 날짜 이동은 시작 때 뷰포트 중앙의 시각을 잡아 위치가 바뀔 때마다 이 오프셋을 적용한다(기존 핀치 앵커는 그대로).
- **`DayMoveModel`**: 명시적 상태 머신 `resting / dragging / settling`. `position`, `velocity`(일/초), `target`, `bounds`. 이벤트: `beginDrag`, `drag(to:)`(경계 안으로 clamp), `release(velocity:)`(플릭은 `v·0.15`일 앞에 착지, 최대 3일), `retarget(to:/by:)`, `advance(by:)`. 정착은 임계 감쇠 스프링(ω=14)을 **해석적으로** 푼다 → 프레임 간격과 무관(1/60×12 = 0.2초 한 번과 오차 < 1e-9). 어느 단계에서든 어떤 이벤트든 받을 수 있다: 비행 중 드래그는 현재 위치에서 인계(반전에 점프·대기 없음), 비행 중 탭은 현재 속도를 유지하고 목표만 바꿈(빠른 연타는 누적: +1+1+1 = +3, 경계에서 멈춤), 경계 밖으로 나가지 않음.

## 검증 (테스트 `ContinuousGridTests` 15개 포함, 전체 337개 통과)
- **좌표·가상화**: 날 폭 고정, 위치·변위 변환, 음수 포함 위치 −3…40을 훑으며 보이는 날 수 ≤ 3 이고 보이는 날은 실제로 창에 닿고 그 밖의 날은 닿지 않음. 계획 날 ≤ 5.
- **공유 시간**: 정수 위치에서 창의 분할과 같고, 사이는 정확한 직선 보간(경계마다 오차 < 1e-9), 선·전체 높이·칸 수 불변. 위치 1→5를 1/200일 간격으로 훑을 때 모든 일정의 y는 항상 그 분할의 `timeToY`와 같고(모든 열이 같은 시간→y), 한 스텝당 정각 y 이동 < 8pt(점프 없음).
- **캐시·가상화**: 위치 1→5를 0.01 간격(400프레임)으로 훑으면 분할 계획 **5회**(창 1…5 한 번씩), 프로필 ≤ 9개, 엔티티는 화면에 한 번이라도 있었던 6일만 생성. 되돌아갔다 다시 가도 **새 계획·프로필·엔티티 0건**, 적중률 > 90%. 캐시 한도 3에서 항목 ≤ 6, 설정이 바뀌면 다른 키(재사용 없음).
- **identity**: 위치 1…5(0.07 간격)의 모든 그려진 날에서 일정·거래 ID 집합이 항상 원본과 같고 위치가 달라져도 ID와 시각은 변하지 않음.
- **상태 모델**: 드래그 clamp, 플릭 착지·hop 제한, 정착 수렴(<90프레임에 정확히 목표 위치·속도 0), 프레임율 무관, 반전·빠른 연타·비행 중 탭의 연속성(반전 후 프레임당 최대 이동 < 0.2일), 같은 이벤트 열은 같은 궤적(결정적), 항상 경계 안.
- **앵커**: 줌 1·1.5·2·3.7·5·8 × 시각 3개(10:30, 13:15, 15:00)에서 위치 1→5→1을 훑을 때 한계에 닿지 않는 모든 스텝의 시각 오차 **< 1e-6분**, 줌 ≥ 2에서는 한계에 닿는 스텝 0개, 왕복하면 오프셋이 정확히 원래로 복귀, 줌 1×는 스크롤이 없어 오프셋 0(시각을 유지할 수 없음). 하루의 양 끝(00:20, 23:50)은 오프셋이 0/최대에서 멈추고 잔차 > 0으로 보고.
- **프레임 비용**: 정착 중 한 프레임(분할 보간 + 열 3개 배치 + 정각 축, 줌 3×)이 **평균 0.22ms (Debug)**, 분할 계획 0회·프로필 0회. 기존 핀치·시간축·글자 충돌 테스트 전부 통과.

## DEBUG 비교 화면 (`-render-continuous`)
- 패널: 위치(일)·단계·목표·속도, 그리는 날/계획 날, 계획·프로필·적중률·엔티티 수, 공유 y(12:00), 앵커 시각과 상태(유지/한계 잔차), 앵커 ON/OFF(pt 유지와 비교). 버튼 −3 −1 +1 +3(연타는 누적), p 슬라이더, 핀치 줌과 함께 동작. 열은 `x = (day − position)·dayWidth`에 놓이고 화면에 닿는 날만 그린다.
- 스크린샷: `move-p0.25-z1`, `move-p0.5-z1/z3/z8`(두 날 사이, 줌 1·3·8). 녹화: `days-anchor-on.mp4` / `days-anchor-off.mp4`(줌 3×, 12:00을 중앙에 두고 +1 +1 +1 연타, 비행 중 −2 반전, −3, +4: 앵커 ON은 중앙 시각 유지, OFF는 오프셋(pt)만 유지).
- 시뮬레이터에서 실제로 확인: 줌 3×에서 스크롤 후 "+1" 탭 → 위치 2.000, 중앙 시각 13:49 유지("유지"), 계획 횟수 불변; p=0.5 스크린샷(그리는 날 1…3, 계획 날 0…4). **녹화 영상 자체는 열어 보지 못했다.**

## 남은 문제
- 실제 스와이프 제스처(속도 추정·가로/세로 중재)는 이번에 만들지 않았다. 화면의 가로 드래그는 이전 DEBUG 입력을 모델에 연결한 것이다.
- 정착 중 확대·스크롤을 사용자가 만지면 앵커 시각이 새로 잡히지 않는다(이동이 끝나 정지한 뒤 다음 이동에서 새로 잡음).
- 하루의 양 끝 시각과 1×에서는 중앙 시각을 유지할 수 없다(그리드가 허용하지 않음); 이 경우 오프셋이 한계에 멈추고 잔차를 패널에 보고한다.
- 날짜 경계(범위 밖)는 hard clamp다. 무한 수평선이지만 이 fixture는 9일이라 창이 1…5로 제한된다. 범위 확장 시 날짜 단위 지연 로딩 정책이 필요하다.
- 화면 시작 때 뷰포트가 몇 번 바뀌어 초기 계획이 몇 번 더 돈다(상태줄 "최적화 4~6회"); 이후 이동에서는 증가하지 않는다.
