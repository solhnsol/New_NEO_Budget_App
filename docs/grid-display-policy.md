# 고정 그리드 표시 규칙 (2026-10-16)

Hans가 실기기에서 본 문제(겹친 일정이 서로 같은 자리로 밀림, 얇은 일정에 붙는 헤더, 누를 수 있는지·어느 일정 것인지 안 보이는 거래 줄, 시간축 글자 색이 들쭉날쭉함)를 고친 규칙. 코드는 `EventOverlapAnalysis`, `EventPresentation`, `DayRenderPlan`, `TransactionLineViews.swift`, `HourAxis`.

## 겹친 일정: 앞 카드만 바뀐다

- 겹치면 **앞 카드**(나중에 시작하는 것, 같이 시작하면 짧은 것)만 들여쓴다. 뒤 카드는 혼자 있을 때와 똑같이 그린다(폭·제목 자리 그대로). 앞 카드에 가려진 부분만 안 보인다.
- 앞 카드는 **자기가 올라탄 카드 중 가장 깊은 것보다 한 칸 더** 들여쓴다(한 칸 16pt, 최대 3칸). 예: 점심 12:00–13:00 위에 새 일정 12:30–15:45와 그 안의 스터디 12:30–14:30 → 점심 0칸, 새 일정 1칸, 스터디 2칸. 예전에는 새 일정과 스터디가 둘 다 1칸이라 같은 자리에 포개졌다.
- 레인(나란히 칸 나누기)은 쓰지 않는다. 카드는 열 폭에서 들여쓴 만큼만 좁아진다.
- 밑에 깔린 카드가 끝나면 다음 카드는 다시 0칸에서 시작한다.

## 크기별 표시 (E0–E4)

높이만으로 정한다. 줄어들 때 사라지는 순서: 거래 행 → 끝 시각 → 시작 시각 → 제목 → 작은 제목.

| 높이(기본 글자 크기) | 보이는 것 |
|---|---|
| 25pt 이상 | 제목(보통 크기), 시작·끝 시각, 거래 행/건수 |
| 19–25pt | 제목이 보통 크기로 들어오고 작은 제목은 같은 만큼 빠진다 |
| 13–19pt | **카드 안 작은 제목**(보통 제목의 70% 크기, 카드 높이 가운데) |
| 13pt 미만 | 글자 없음(카드 또는 선만, 눌러서 열 수는 있다) |

얇은 카드는 더 이상 카드 위에 탭(헤더)을 달지 않는다. 헤더는 제목이 들어갈 만큼 높은 카드의 제목이 거래 줄과 부딪칠 때만 엔진이 붙인다. 날짜를 넘기는 동안에는 쉬고 있을 때의 결정(`holdingVisibility`)을 그대로 쓴다.

## 거래: 금액 칩 + 꼬리선 (Hans 선택, 2026-10-16)

- 거래 줄은 그 시각에 **흰 둥근 칩**(카테고리 아이콘·이름·금액)으로 그린다. 앱의 다른 버튼과 같은 모양이라 눌러서 열고 길게 눌러 옮길 수 있는 것으로 읽힌다.
- 일정에 연결된 거래는 칩 테두리와 시각 점이 **그 일정의 색**이다. 연결 안 된 거래는 회색.
- 연결된 거래가 일정 시간 밖이면 일정 카드의 왼쪽 띠가 **점선 꼬리**로 카드 가까운 끝에서 거래 시각까지 이어진다.
- 일정 시간 안의 연결 거래는 지금처럼 카드 안 행으로 쓴다.
- 고르지 않은 안: 하루 칸 오른쪽 금액 레일, 그리드에서 거래 빼기.

## 왼쪽 시간축

- 그리드 가로줄에 걸린 시각은 **진한 글씨, 굵게, 보통 크기**(`Theme.textPrimary`). 나머지 시각은 **회색, 15% 작게**(`Theme.textTertiary`).
- 자리가 모자랄 때 그리드 줄 시각이 먼저 자리를 차지한다(`HourAxis.layout(first:)`). 날짜를 넘기며 줄이 오가는 시각은 두 모양이 서로 넘어간다.
